---
description: 프로젝트 설계 및 기획 워크플로우 (Design Workflow)
---

이 워크플로우는 코드를 작성하기 전에 체계적인 설계를 수행하여 **유지보수성**, **확장성**, **효율성**, **신뢰성**을 확보하는 것을 목표로 합니다.

1. **요구사항 분석 및 목표 정의 (Requirement Analysis)**
   - 사용자의 요청 사항을 명확히 분석합니다.
   - 기능의 목적, 타겟 사용자, 예상되는 동작 시나리오를 정의합니다.
   - **핵심 질문**: "이 기능이 왜 필요한가?", "이 기능이 기존 시스템에 어떤 영향을 미치는가?"

2. **현행 아키텍처 및 의존성 검토 (Architecture Review)**
   - `README.md`의 현재 시스템 아키텍처를 검토합니다.
   - 기존 모듈, 데이터 구조(Store), 외부 API와의 의존성을 파악합니다.
   - **체크리스트**:
     - 기존 컴포넌트 재사용 가능 여부
     - 전역 상태(Zustand) 변경 필요성
     - API 프록시 또는 새로운 데이터 소스 필요 여부
     - 성능 영향 (렌더링, 네트워크 트래픽)

3. **기본 원칙 및 컨벤션 확인 (Conventions Check)**
   - `GEMINI.md`와 `.agent/skills/SKILL.md`를 참조하여 코딩 컨벤션 및 디자인 시스템 규칙을 확인합니다.
   - **필수 준수 사항**:
     - 디자인 시스템: `shadcn/ui`, `Tailwind CSS`
     - 상태 관리: `Zustand` (순수성을 지킬 것)
     - API 호출: 반드시 프록시 사용 (CORS 방지)
     - 파일 구조: 기능별/컴포넌트별 명확한 분리

4. **상세 설계 문서화 (Update Design Documents)**
   - **설계의 핵심 단계입니다.** 코드를 작성하기 전에 문서를 먼저 업데이트합니다.
   - **`README.md` 업데이트**:
     - [ ] **기능 명세**: 새 기능의 상세 동작 기술
     - [ ] **UI/UX 설계**: 화면 레이아웃, 인터랙션 정의 (필요시 텍스트 기반 와이어프레임)
     - [ ] **데이터 흐름**: API <-> Store <-> Component 흐름 정의
     - [ ] **기술 스택**: 새로 추가되는 라이브러리나 기술 정의
   - **`.agent/skills/SKILL.md` 업데이트** (필요시):
     - 새로운 개발 패턴이나 에이전트 행동 수칙이 생기면 스킬 문서에 추가합니다.

5. **설계 검토 및 피드백 (Design Review)**
   - 작성된 설계(`README.md` 변경안)를 사용자에게 제시하고 승인을 받습니다.
   - 예상되는 리스크와 대안을 함께 제시합니다.

6. **작업 계획 수립 (Action Plan)**
   - 설계에 따른 세부 구현 작업(Task) 목록을 작성합니다.
   - 구현 순서: `데이터 구조(Store/API)` -> `비즈니스 로직(Hook)` -> `UI 컴포넌트` -> `통합`

---
**Tip**: 설계는 변경될 수 있지만, 명확한 기준점(Baseline)을 잡고 시작하는 것이 중요합니다. 설계 문서가 곧 개발의 나침반이 됩니다.
